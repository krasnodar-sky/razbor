# Грабли — чек-лист типовых ловушек перед глубокой диагностикой

Каждый паттерн добыт из реальных инцидентов (майнинг журналов работы ИИ-агентов, не теория). Формат: сигнал → проверка. Пробегай список ДО того, как строить сложные гипотезы: половина «загадочных» проблем закрывается здесь.

**Карта по моментам** (нумерация сквозная и не меняется — на номера ссылаются журналы; читай группу под свой момент, не весь список):
- **Вход в диагностику** («странно», «не работает», «мертво»): 1–4, 6–8, 13–14, 21, 24–25, 34, 39.
- **Цифры, сравнения, чужие данные**: 5, 10, 18, 20–21, 30, 39.
- **Перед мутацией и выкаткой** (короткий блок ⚡ внизу): 9, 11, 16–17, 19, 22–23, 26–27, 31, 36, 41–42.
- **Инструменты, гейты, промпты, тесты**: 11–12, 15, 28–29, 32, 35, 37–38.
- **Автономные контуры** (крон, автопилот, слушатель): 2, 33–35, 40.

1. **Оптимистичный интерфейс врёт.** Действие «выглядит выполненным» (клик прошёл, DOM обновился, API ответил ok), а реально не закоммитилось. → Успех подтверждай только независимым перечитыванием: перезагрузка страницы, свежий процесс, отдельный запрос к живой системе.

2. **Молчаливые сбои.** Фоновый процесс, cron или деплой «завершился успешно», а функция не выполняется неделями. → Проверяй артефакты и свежесть данных (дата изменения БД, реальные исходящие сообщения, содержимое результата), не код выхода и не зелёный статус.

3. **Зомби-состояние среды.** Осиротевшие процессы, туннели, инстансы от прошлых запусков ломают текущую задачу (два бота на одном токене, зависший headless-браузер, мёртвый VPN-интерфейс). → При загадочном сбое первым делом ищи остатки прошлых запусков; висит страница — сначала просто reload. Второй экземпляр того же приложения (чужой профиль, параллельная сессия) перехватывает команды, а ошибка называет не ту причину («не запущен» = «не тот инстанс»): чужой не убивать, после каждой команды сверять, что попал в нужный.

4. **Какая копия боевая?** Несколько машин/клонов/копий файла — компоненты смотрят в разные. → Перед выводами определи боевую копию по дате и содержимому и проверь, что все компоненты (cron, сервис, данные) смотрят на неё. Локальный клон ≠ прод.

5. **Странная цифра.** Метрика удивляет — но вывод из неё делать рано. → Сначала: как цифра физически формируется, что её обнуляет или искажает (нулевой расход при нулевом остатке = дефицит, а не отсутствие спроса)? Потом арифметика правдоподобия на пальцах.

6. **«Такого нет».** Хочется ответить «инструмента/файла/возможности не существует». → Сначала файловая или фактовая проверка (ls, find, поиск в документации), потом отрицание. Один запрос дешевле ложного «нет». Зеркальный случай — «такое уже есть» и «это запрещено»: перед тем как предлагать владельцу доработку, grep по его источникам правды (правила, промпт, база) — предложить то, что владелец сам запретил, стоит дороже лишнего grep.

7. **Рецидив.** Проблема уже случалась и «была решена». → Прошлый фикс лечил симптом. Подними прошлый разбор и ищи, чем он был неполон; корень часто на уровень глубже (не «дубль погашен», а «CI оживляет дубль при каждом деплое»). Обратная ловушка: тот же симптом ≠ та же причина — прошлый диагноз лишь одна из 3+ гипотез, его улики снимай заново (в прошлый раз «сеть», в этот — деградировавший долгоживущий процесс клиента при здоровой сети).

8. **Единственный рабочий канал — сначала заметка, потом дебаг.** Упёрся в доступ к хосту, кабинету или API → ПЕРВОЙ командой grep памяти и журнала по имени системы: у капризной системы обычно один задокументированный рабочий путь, остальные стабильно виснут. Чинить сеть, прокси или клиент — только после чтения записи. Не ретрай сломанный путь — иди задокументированным; у внешней платформы часто есть мгновенный валидатор или сухой прогон — не перебирай вслепую. Стоп от собственного гейта — не искать обход, а повторить по протоколу гейта.

9. **Правка рвёт соседей.** «Безобидное» изменение поля/файла рушит внешние связи (переименование удаляет сопоставление в интеграции, ручная правка конфига перезаписывается живым планировщиком). → Перед правкой перечисли, кто ещё читает/синкает этот объект.

10. **Генеративный пересказ вместо источника.** LLM-извлечение и пересказы галлюцинируют — уверенно и правдоподобно. → При расхождении данных сверяйся с сырым первоисточником (сырой файл, ответ API, документ), не с интерпретацией. Свой субагент, свой скрипт, авто-метка платформы (AI-описание, «зрение» бота, статус выполнения) — тоже пересказ: число или вердикт из отчёта — гипотеза до прогона по живым данным своими руками.

11. **Секреты по содержимому, не по именам.** Перед публикацией наружу токен может жить в любом файле, не только в .env. → Скан по содержимому всех файлов, не по расширениям.

12. **Обещание вне носителя.** «Напомню», «проверим позже», недоделка в чате → потеряется. → Каждое обещание и отложенный замер — в персистентный носитель (журнал недоделок, планировщик) с датой.

13. **Внешний API отрезал по IP-региону — позже.** Сервис, неделями штатно ходивший во внешний API с данного хоста, внезапно ловит 403/блок: провайдер API сменил edge-политику (WAF, гео), а не вы что-то сломали. → При сбое внешнего вызова первым делом сравни голый запрос БЕЗ ключа с того же хоста и тот же запрос с контрольного хоста в другом регионе: коды разошлись = блок по egress-IP, ключ/код ни при чём; лечение — прокси/туннель через хост разрешённого региона. Следствие: смена хостинга = смена egress-IP — проверяй доступность всех внешних API с нового IP и помни, что блок может прийти не сразу. Тот же класс — вердикт «мертво / недоступно / не существует» от субагента или облачного инструмента с ДРУГОГО egress-IP: гипотеза до проверки с IP целевого региона.

14. **Статус — в кабинете первоисточника, не в уведомлениях.** Подал заявку во внешнюю систему, тишина трактуется как «в обработке» — а уведомления об отказе не отправляются, падают в спам/«Рассылки» или существуют только в ЛК. → Не ждать письма: активно опрашивать авторитетную страницу статуса в кабинете. Тишина ≠ обработка.

15. **Проверь саму проверку.** Тест/инвариант всегда зелёный — или независимая проверка говорит «фикс не сработал». Проверка может врать в обе стороны. → Вечнозелёную проверку один раз сломай намеренно (подай битый вход — увидь красный); при «ложном провале» — позитивный контроль канала (видит ли он заведомо применённую правку, ту ли версию артефакта читает). Тест не должен делить посылку с кодом (тот же порог/эвристика = не проверяет ничего) и обязан идти боевой траекторией пользователя. Три формы лживых тестов: тест сам подставляет аргумент, который прод не передаёт (нужен тест на ТОЧКУ ВЫЗОВА); сводка сюиты склеивает пустой вывод упавшего теста со строкой соседа (у каждого теста — своя заглушка «НЕТ ИТОГА»); предупреждение, которое горит ВСЕГДА, равно отсутствию предупреждения. Отдельно: упавший тест с говорящим именем («…не сломан», «…не удалён») — зафиксированное решение владельца: откатывай правку, не чини тест.

16. **Деплой ≠ активация.** Фикс задеплоен/закоммичен, а поведение прежнее: резидентный процесс держит старый код/конфиг/токены до рестарта; «подхватится само» верно только для процессов, стартующих заново на каждый запуск. → Сверь время старта живого процесса с временем деплоя и проверь поведение именно живого процесса. Обновляешь компонент на нескольких машинах — обнови и проверь ВСЕ. Совпадающий номер версии ≠ совпадающее содержимое: у обновляемого артефакта сверяй содержимое, при любой правке бампай версию — иначе апдейтер честно скажет «уже последняя» про чужое. Три проверки активации до рапорта «работает»: прод реально передаёт новый аргумент (тест на точку вызова), у новой ветки есть своя лог-строка и она ПОЯВИЛАСЬ после выкатки, у нового поля конфига есть читатель (grep: ноль читателей = комментарий, не настройка).

17. **Факт живёт во многих местах, у дефекта много входов.** Правишь факт в очевидном месте или чинишь поведение на одном пути — а копии факта осели в других хранилищах (файлы, БД, промпты, тексты), и в дефект ведут другие входы (кнопка, крон, автопилот). → Перед фиксом перечисли ВСЕ места записи факта и ВСЕ входы в поведение (искать по ЗНАЧЕНИЮ, не по имени функции) и закрой их одной общей точкой, а не заплаткой на каждый вход; фикс в одном — отсрочка рецидива, не фикс. Отдельно спроси: «сколько всего дефектов?», а не только «где дефект?». Нашёл дубль факта — свести к одному источнику СЕЙЧАС или хвост с датой; «ещё не выстрелило» — не причина оставить.

18. **Семантику внешнего поля — по своим сырым данным.** Дизайн опирается на поле/эндпоинт чужого API, известные из доков, совета или ревью. → До внедрения выгрузи свои реальные события и посчитай: существует ли поле, какие значения принимает на граничных случаях. Доки и уверенность ревьюера — гипотеза; своё сырьё — факт. Обратная сторона — свои выгрузки: края распределения (записи по 1 ₽ при медиане в десятки тысяч) проверяй отдельно, задав коридор от медианы; фильтр и гейт строй по структурному полю, не по словам в названии, и печатай счётчики ложных плюсов и минусов после каждого условия.

19. **Перед необратимой отправкой — перечитай итоговый артефакт.** Сообщение/документ уходит вовне через цепочку инструментов, отправка неповторима или дорога. → Перечитай СОБРАННЫЙ финальный артефакт целиком (тело, не заголовок) тем же путём, каким он уйдёт, — до нажатия. Пост-проверка тут не спасает: попытка уже сожжена.

20. **Извлечённый/перенесённый текст — не оригинал.** OCR, текстовый слой PDF, innerText, буфер обмена, heredoc: содержимое «успешно» переносится, но порядок пар едет, ячейки склеиваются, гомоглифы и невидимые символы ломают поиск и сравнение. → Критичное сверяй по независимому представлению того же источника: рендер в картинку и глаза, счётчики элементов «N/M», побайтовое сравнение после переноса между средами. Имя, путь или подпись, обещающие оригинал («/origin/», «трек организатора»), — не оригинал: промерь (Content-Length, разрешение из заголовка, число точек). Данные, обрезанные ТВОИМ ЖЕ выводом (срез для печати), — не улика о данных. Медиа и генеративный результат сверяй глазами и наложением, не числами и не описанием.

21. **Ресурс кончился — кто ещё ест и на каком этаже лимит.** Модель «тупит», ответы обрываются, сервис требует оплату при живом лимите, ключ сгорел необъяснимо быстро. → До починки промптов и кода: баланс и лимиты на ВСЕХ уровнях иерархии (запрос/ключ/аккаунт/провайдер), инвентаризация всех потребителей того же ресурса (включая скрытых: фоновые сервисы на том же ключе, внутренние размышления модели), finish_reason в ответе. Свой счётчик расхода ≠ счёт провайдера (запись в кэш идёт с наценкой к базовому тарифу, reasoning-токены, сорванные вызовы) — сверяй по кабинету биллинга. Ресурс — не только деньги и токены: квота ФАЙЛОВ (иноды) при свободном месте; обрезка ровно по степени двойки = буфер. Диагностические зонды сами выжигают лимит, а короткие зонды провайдер режет защитой при живом ключе — диагноз ставь по журналу боевых вызовов.

22. **Смена формата отпечатка над живым хранилищем = ложная волна «изменилось».** Дифф-система (монитор, синк, инвалидация кэша) хранит отпечатки объектов; правка алгоритма отпечатка — новое поле в хеше, другая нормализация — первым же прогоном делает ВСЕ существующие объекты «изменёнными»: залп ложных уведомлений/пересинков. Симптом: сразу после деплоя «новых: 0, изменённых: ВСЁ». → Перед включением пересчитай отпечатки существующих объектов молча (миграция хранилища) или сделай первый прогон тихим — и только потом включай рассылку.

23. **Операция рвёт канал, по которому сама пришла.** Рестарт или остановка сервиса, который держит твой доступ (туннель, VPN, сетевой демон), либо широкий kill по шаблону, совпадающему с собственной командной строкой, убивает саму операцию: команда не доводится до конца, результат не виден, а иногда теряется и сам доступ. Симптом: команда «зависла» и вернулась ошибкой соединения, состояние неизвестно. → Перед действием спроси, идёт ли твой канал через объект действия. Если да — запускай отложенно и независимо от сессии (таймер/планировщик на несколько секунд вперёд), а не напрямую. Для массового kill бери точные PID: шаблон по командной строке матчит и того, кто его выполняет.

24. **Проба порта фиксированным числом байт даёт ложный «мёртв».** Живость сервиса проверяется чтением приветствия на N байт, а баннер короче N — чтение блокируется до таймаута, и живой сервис записывается в мёртвые. Дальше диагноз уезжает к «сервер лёг» и лечится не то. → Читай первую СТРОКУ (или первый байт с коротким таймаутом) и различай три разных исхода: отказ (порт закрыт), молчание (канал ведёт в никуда), баннер (сервис жив). Не строй вывод «сервис упал» на одной пробе одним способом. Шире: любой «мёртв» от одной пробы (порт, инстанс приложения, API, субагент) — гипотеза; подтверждай вторым, независимым способом.

25. **Проброшенный порт занят мёртвой сессией.** Постоянный (в т.ч. обратный) туннель: после сетевого обрыва сессия на принимающей стороне остаётся «установленной» и продолжает держать проброшенный порт, а переподключающийся клиент не может его занять и падает в бесконечном цикле рестартов. Порт при этом ОТКРЫТ и принимает соединения, но данные не идут — снаружи «висит/молчит». Соседние сервисы (сайт, боты, задания) работают и маскируют аварию, поэтому её ищут не там. → На принимающей стороне включи проверку живости сессий на уровне протокола (keepalive-пробы с разрывом после N неответов) — без неё порт освободится только по системному TCP-keepalive, а это часы. Быстрый диагноз: сравни возраст сессии, которая держит порт, со временем старта клиента — расхождение выдаёт залипшую.

26. **База под тобой поехала: параллельный редактор того же артефакта.** Правишь копию долгоживущего объекта (боевой файл, документ, конфиг, таблица), и между снятием копии и записью проходит время — а рядом работает другая сессия, коллега или синк. Собственная правка при этом корректна и тесты зелёные, поэтому тревоги нет; запись просто откатывает чужую работу, и обнаруживается это через дни, когда пропавшую функцию хватятся. → Отпечаток источника, снятый в начале, к моменту записи — просроченная гипотеза: сверяй его повторно НЕПОСРЕДСТВЕННО перед записью, а не в начале работы. Разошёлся — пересобирай правку поверх свежей версии, не дописывай поверх устаревшей копии. Косвенные признаки чужой работы: свежие резервные копии и версии артефакта, записи и функции, которых нет в твоём снимке, недавний перезапуск сервиса. Дифф «моё против текущего боевого» перед выкаткой ловит это дешевле всего: минусы, которых ты не писал, = чужая работа.

27. **Дозапись в файл без завершающего перевода строки склеивает записи.** `>>` в конфиг или список (ключи, хосты, реестры, правила) дописывает запись в КОНЕЦ последней строки, если файл не оканчивался переводом строки: команда вернула успех, файл выглядит правдоподобно, обе склеенные записи молча не работают или меняют смысл. Тот же класс — замена по шаблону/якорю: ноль совпадений (лишний пробел, другой разделитель) — тоже «успех»; совпало НЕ ТАМ — с заголовком раздела, с соседом, с уже вставленной копией себя (проверка «уже применено» врёт, если замена содержит якорь). → Перед дозаписью проверь последний байт файла, добавь ведущий перевод строки. Замена — только через сухой прогон с отчётом «применено / не найдено / несколько совпадений», потом применение, потом md5 против эталона. Результат верифицируй разборщиком формата (валидатор конфига, парсер списка), не глазами: он покажет записи по одной и выдаст склейку.

28. **Локальный костыль — маркер общей дыры.** В кодовой базе на одном из путей стоит точечная заплатка: обрезка поля до лимита, ретрай, спец-обработка ошибки — значит, на эти грабли уже наступали и залатали ровно то место, где болело; остальные пути с тем же дефектом остались дырявыми и молчат (платформа усекает/отбрасывает без ошибки, задание помечается выполненным). → Найдя костыль, не проходи мимо: грепни тот же паттерн по ВСЕМ путям той же операции и почини общую точку, а не соседний случай. Обратное тоже верно: узнав лимит поля внешней платформы, проверь все места, где твой код в это поле пишет, и приёмку делай по факту доставки ЦЕЛИКОМ на принимающей стороне, не по статусу отправки.

29. **Область действия предохранителя — измерять, не предполагать.** Гейт, лимит, правило или запрет стоит на одном пути (одна папка, один инструмент, один канал, одна сессия), а сработать должен на всех: сессия из чужой папки не читает проектную память, хук на команды не видит правку файла, гейт сессии не защищает код на сервере, «первым не писать» действует на бота, но не на юзербота. → Для каждого предохранителя запиши ТРИ вещи: где стоит, какие пути обходят его конструктивно, какой тест это показал. Проверяй с обходного пути (чужая папка, другой инструмент, другая машина), не с того, где писал.

30. **Сравнение «до/после» без сопоставимости.** Две цифры, два скриншота, два состояния — но разные периоды, фильтры, единицы или методики выгрузки (месяц против недели, «просмотры» против «переходов», выборка против полного ряда). Вывод выглядит очевидным и неверен. → До вывода: сравниваемые ряды получены одним способом, за сопоставимый период, по одному определению? Нет — привести к общему знаменателю или не сравнивать.

31. **Привилегированная запись рядом с живым сервисом меняет владельца.** Запуск скрипта, распаковка, копирование или скачивание от root в каталог, где сервис работает под другим пользователем: новые файлы и папки остаются root'овыми, сервис молча теряет запись, ошибка всплывает через дни в другом месте. → Работа в каталоге сервиса — от его пользователя; если от root — смена владельца перед уходом и проверка списком файлов: владелец каждого нового файла = пользователь сервиса.

32. **Гейт классифицирует по поверхностному признаку.** Барьер (хук, фильтр, обёртка, валидатор) решает по подстроке, имени файла, наличию символа или слову в команде — и стопит чтение, пропускает запись в обходной форме, горит на безобидном синтаксисе. Ложные стопы учат обходить гейт, ложные пропуски превращают его в декорацию. → У каждого гейта — набор кейсов (подлинные срабатывания + все наблюдённые ложные), прогон до и после каждой правки; каждый ложный стоп в бою = новый кейс, не «ну ладно». Матчить признак ДЕЙСТВИЯ (запись, отправка), а не признак контекста (упоминание пути).

33. **Автономный контур откатывает решения владельца.** Крон, автопилот или синк «восстанавливает» состояние по своему правилу (снятый с продажи товар, выключенный модуль, изменённая цена) — а владелец это выключил сознательно. Контур не знает о решении, потому что оно записано в чате, а не в носителе, который контур читает. → Каждое ручное решение владельца по автоматизируемому объекту — в носитель, который контур читает (стоп-лист, флаг в конфиге, поле в базе), с датой и причиной; контур перед «восстановлением» обязан сверяться со стоп-листом.

34. **Полуживой контур: выход работает, вход отключён.** Компонент выключен «на время» (модуль ответов, парсер, канал), остальная система работает и маскирует пропажу: отчёты идут, статус зелёный, а функция не выполняется неделями. Это не «сломалось», это «забыли включить». → Первым делом — не выключен ли вход намеренно: флаги и конфиг компонента, стоп-лист отключений (№33), журнал за дату, когда функция пропала. Нашёл «временно выключено» — это не сбой, чинить нечего; включать ли обратно — решение владельца, не твоё. Профилактика: у каждого временного отключения — дата возврата и хвост в носителе; регулярный дайджест перечисляет ОТКЛЮЧЁННЫЕ контуры отдельной строкой, пока они отключены.

35. **Канал наружу без предохранителя = правило без механизма.** Инструкция «отправлять только после апрува» живёт в памяти или промпте, а канал отправки (скрипт, очередь, бот, слушатель) технически открыт любой сессии и любому автономному контуру. Инструкция не сматчилась дважды — и ушли сообщения живому человеку. Тот же класс: слушатель без фильтра по месту отвечает в чужие чаты. → Правило «только с апрувом» внедрено, когда есть механизм (хук, флаг, белый список адресатов и чатов), который останавливает без участия памяти и работает из ЛЮБОЙ папки и сессии (область действия и тест с обходного пути — №29).

36. **Страховка-декорация.** Бэкап, фолбэк, резервный канал или откат «есть» — а ни разу не срабатывал, не проверялся или перестал делаться месяц назад (крон умер, папка переехала, права сменились). Обнаруживается в момент, когда нужен. → Раз в месяц один прогон каждой страховки: восстановить файл из бэкапа, переключиться на фолбэк, откатить тестовое изменение — и дата последнего успешного прогона рядом со страховкой. Страховка без даты прогона = отсутствие страховки.

37. **Служебные записи в одном ряду с содержательными.** Тесты, пробы, пинги, заглушки и «проверка канала» пишутся в тот же журнал, чат, базу или список, что и боевые записи, без пометки — и потом считаются фактами: дайджест цитирует тестовое сообщение, метрика включает пробные заказы, разбор ищет инцидент, которого не было. → Служебное — с явным маркером в самой записи (`[test]`, отдельный чат, поле is_test) и уборкой сразу после проверки; все читатели носителя (дайджест, метрики, разбор) фильтруют маркер.

38. **Позиция инструкции в промпте = её приоритет.** Правило в конце длинного промпта, внутри абзаца или после примеров теряет силу: модель следует тому, что в начале и отдельной строкой. Симптом: «правило есть, формулировка ясная, а не соблюдается». → Промпт — как код: критичные правила первыми и отдельными строками, одно правило — одна строка, императивно; после правки промпта — тот же кейс заново (прогон до и после каждой правки — №32), не новый.

39. **Нулевой результат ≠ параметр проигнорирован.** Фильтр, флаг, ключ конфига или аргумент API «не работает»: вернулось пусто или без изменений. Но «пусто» может значить «работает, подходящих данных нет», а «без изменений» — «применён, на этих данных незаметен». → Контрольный замер: подай данные, на которых параметр ОБЯЗАН дать отличие, и покажи разницу; только потом «игнорируется».

40. **Фикс с TTL.** Правка с истечением — сертификат, список отзыва, cooldown, окно, токен, срок подписки, «временно до …» — заработала сейчас и молча кончится в дату, которую никто не записал. Отдельная форма: «сбой прошёл сам» — это отложенный рецидив, не решение. → У каждого фикса с датой истечения — дата в носитель с напоминанием ДО истечения; «прошло само» = разбор причины или хвост с датой перепроверки.

41. **Общее git-дерево у параллельных смен.** Две сессии (или сессия и крон-деплой) работают в одном клоне: `git add -A` уносит чужие незакоммиченные правки в чужой коммит, `reset`/`stash`/`checkout` их стирает, деплой выкатывает половину чужой работы. → Каждой смене — свой клон или worktree; перед любым `reset`/`stash`/`checkout` — `git diff` в файл с датой; в коммит — только свои файлы по имени, не `-A`.

42. **Эфемерные рабочие папки.** Результат дороже часа работы (выгрузка, парс, расшифровка, черновик) лежит только в scratch, tmp или папке сессии, которая чистится сама или недоступна другой сессии. → Артефакт дороже часа — сразу во второе место (репозиторий, папка проекта, сервер) с именем и датой; scratch — для промежуточного, не для результата.

## ⚡ Перед мутирующей операцией

Отдельный короткий блок, потому что момент другой: эти вопросы задаются ПЕРЕД действием, а не на входе в диагностику — иначе к моменту записи они уже забыты.

- **Пишу в конфиг или список?** Файл оканчивается переводом строки? После записи — прогнать разборщиком формата, а не просмотреть глазами (№27).
- **Правлю заменой по шаблону или патчем по якорю?** Сухой прогон с отчётом «применено / не найдено / несколько совпадений» — ноль совпадений и совпадение не там тоже возвращают «успех»; после — md5 против эталона (№27).
- **Рестартую сервис или бью процессы по шаблону?** Не идёт ли мой собственный канал через объект действия и не матчит ли шаблон мою же команду (№23).
- **Пишу от root в каталог сервиса?** Кто владелец новых файлов — список файлов после, смена владельца до ухода (№31).
- **Утверждаю «есть бэкап/откат»?** Покажи файл бэкапа именно от ЭТОЙ выкатки: путь, дата, размер (№36).
- **Добавляю поле, флаг, аргумент?** Кто его читает — grep до коммита; ноль читателей = не настройка (№16).
- **Упал тест с говорящим именем?** Это решение владельца — откати правку, не чини тест (№15).
- **Общее git-дерево?** `git diff` в файл ДО reset/stash; в коммит — свои файлы по имени, не `-A` (№41).
- **Результат дороже часа лежит только в рабочей папке?** Второе место хранения — сейчас, не «потом» (№42).

## Как пополнять

Новая грабля из боевого разбора → обобщи до паттерна «сигнал → проверка» (без локальных путей, имён, ID) → допиши сюда → commit + push → `claude plugin update razbor` на машинах. Конкретику этой грабли (пути, каналы, названия систем) фиксируй в памяти своей машины.
