# Грабли — чек-лист типовых ловушек перед глубокой диагностикой

Каждый паттерн добыт из реальных инцидентов (майнинг журналов работы ИИ-агентов, не теория). Формат: сигнал → проверка. Пробегай список ДО того, как строить сложные гипотезы: половина «загадочных» проблем закрывается здесь.

1. **Оптимистичный интерфейс врёт.** Действие «выглядит выполненным» (клик прошёл, DOM обновился, API ответил ok), а реально не закоммитилось. → Успех подтверждай только независимым перечитыванием: перезагрузка страницы, свежий процесс, отдельный запрос к живой системе.

2. **Молчаливые сбои.** Фоновый процесс, cron или деплой «завершился успешно», а функция не выполняется неделями. → Проверяй артефакты и свежесть данных (дата изменения БД, реальные исходящие сообщения, содержимое результата), не код выхода и не зелёный статус.

3. **Зомби-состояние среды.** Осиротевшие процессы, туннели, инстансы от прошлых запусков ломают текущую задачу (два бота на одном токене, зависший headless-браузер, мёртвый VPN-интерфейс). → При загадочном сбое первым делом ищи остатки прошлых запусков; висит страница — сначала просто reload.

4. **Какая копия боевая?** Несколько машин/клонов/копий файла — компоненты смотрят в разные. → Перед выводами определи боевую копию по дате и содержимому и проверь, что все компоненты (cron, сервис, данные) смотрят на неё. Локальный клон ≠ прод.

5. **Странная цифра.** Метрика удивляет — но вывод из неё делать рано. → Сначала: как цифра физически формируется, что её обнуляет или искажает (нулевой расход при нулевом остатке = дефицит, а не отсутствие спроса)? Потом арифметика правдоподобия на пальцах.

6. **«Такого нет».** Хочется ответить «инструмента/файла/возможности не существует». → Сначала файловая или фактовая проверка (ls, find, поиск в документации), потом отрицание. Один запрос дешевле ложного «нет».

7. **Рецидив.** Проблема уже случалась и «была решена». → Прошлый фикс лечил симптом. Подними прошлый разбор и ищи, чем он был неполон; корень часто на уровень глубже (не «дубль погашен», а «CI оживляет дубль при каждом деплое»).

8. **Единственный рабочий канал.** У капризной внешней системы часто есть один задокументированный рабочий путь, а остальные стабильно виснут. → Перед дебагом проверь записи: не задокументирован ли уже рабочий канал. Не ретрай сломанный путь — иди задокументированным.

9. **Правка рвёт соседей.** «Безобидное» изменение поля/файла рушит внешние связи (переименование удаляет сопоставление в интеграции, ручная правка конфига перезаписывается живым планировщиком). → Перед правкой перечисли, кто ещё читает/синкает этот объект.

10. **Генеративный пересказ вместо источника.** LLM-извлечение и пересказы галлюцинируют — уверенно и правдоподобно. → При расхождении данных сверяйся с сырым первоисточником (сырой файл, ответ API, документ), не с интерпретацией.

11. **Секреты по содержимому, не по именам.** Перед публикацией наружу токен может жить в любом файле, не только в .env. → Скан по содержимому всех файлов, не по расширениям.

12. **Обещание вне носителя.** «Напомню», «проверим позже», недоделка в чате → потеряется. → Каждое обещание и отложенный замер — в персистентный носитель (журнал недоделок, планировщик) с датой.

13. **Внешний API отрезал по IP-региону — позже.** Сервис, неделями штатно ходивший во внешний API с данного хоста, внезапно ловит 403/блок: провайдер API сменил edge-политику (WAF, гео), а не вы что-то сломали. → При сбое внешнего вызова первым делом сравни голый запрос БЕЗ ключа с того же хоста и тот же запрос с контрольного хоста в другом регионе: коды разошлись = блок по egress-IP, ключ/код ни при чём; лечение — прокси/туннель через хост разрешённого региона. Следствие: смена хостинга = смена egress-IP — проверяй доступность всех внешних API с нового IP и помни, что блок может прийти не сразу.

14. **Статус — в кабинете первоисточника, не в уведомлениях.** Подал заявку во внешнюю систему, тишина трактуется как «в обработке» — а уведомления об отказе не отправляются, падают в спам/«Рассылки» или существуют только в ЛК. → Не ждать письма: активно опрашивать авторитетную страницу статуса в кабинете. Тишина ≠ обработка.

15. **Проверь саму проверку.** Тест/инвариант всегда зелёный — или независимая проверка говорит «фикс не сработал». Проверка может врать в обе стороны. → Вечнозелёную проверку один раз сломай намеренно (подай битый вход — увидь красный); при «ложном провале» — позитивный контроль канала (видит ли он заведомо применённую правку, ту ли версию артефакта читает). Тест не должен делить посылку с кодом (тот же порог/эвристика = не проверяет ничего) и обязан идти боевой траекторией пользователя.

16. **Деплой ≠ активация.** Фикс задеплоен/закоммичен, а поведение прежнее: резидентный процесс держит старый код/конфиг/токены до рестарта; «подхватится само» верно только для процессов, стартующих заново на каждый запуск. → Сверь время старта живого процесса с временем деплоя и проверь поведение именно живого процесса. Обновляешь компонент на нескольких машинах — обнови и проверь ВСЕ.

17. **Факт живёт во многих местах, у дефекта много входов.** Правишь факт в очевидном месте или чинишь поведение на одном пути — а копии факта осели в других хранилищах (файлы, БД, промпты, тексты), и в дефект ведут другие входы (кнопка, крон, автопилот). → Перед фиксом перечисли ВСЕ места записи факта и ВСЕ входы в поведение; фикс в одном — отсрочка рецидива, не фикс. Отдельно спроси: «сколько всего дефектов?», а не только «где дефект?».

18. **Семантику внешнего поля — по своим сырым данным.** Дизайн опирается на поле/эндпоинт чужого API, известные из доков, совета или ревью. → До внедрения выгрузи свои реальные события и посчитай: существует ли поле, какие значения принимает на граничных случаях. Доки и уверенность ревьюера — гипотеза; своё сырьё — факт.

19. **Перед необратимой отправкой — перечитай итоговый артефакт.** Сообщение/документ уходит вовне через цепочку инструментов, отправка неповторима или дорога. → Перечитай СОБРАННЫЙ финальный артефакт целиком (тело, не заголовок) тем же путём, каким он уйдёт, — до нажатия. Пост-проверка тут не спасает: попытка уже сожжена.

20. **Извлечённый/перенесённый текст — не оригинал.** OCR, текстовый слой PDF, innerText, буфер обмена, heredoc: содержимое «успешно» переносится, но порядок пар едет, ячейки склеиваются, гомоглифы и невидимые символы ломают поиск и сравнение. → Критичное сверяй по независимому представлению того же источника: рендер в картинку и глаза, счётчики элементов «N/M», побайтовое сравнение после переноса между средами.

21. **Ресурс кончился — кто ещё ест и на каком этаже лимит.** Модель «тупит», ответы обрываются, сервис требует оплату при живом лимите, ключ сгорел необъяснимо быстро. → До починки промптов и кода: баланс и лимиты на ВСЕХ уровнях иерархии (запрос/ключ/аккаунт/провайдер), инвентаризация всех потребителей того же ресурса (включая скрытых: фоновые сервисы на том же ключе, внутренние размышления модели), finish_reason в ответе.

## Как пополнять

Новая грабля из боевого разбора → обобщи до паттерна «сигнал → проверка» (без локальных путей, имён, ID) → допиши сюда → commit + push → `claude plugin update razbor` на машинах. Конкретику этой грабли (пути, каналы, названия систем) фиксируй в памяти своей машины.
